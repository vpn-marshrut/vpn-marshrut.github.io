Как настроить AdGuard DNS: выберите режим и проверьте запросы

Порядок настройки публичного или личного AdGuard DNS: адрес и протокол, Android, iOS, роутер, проверка резолвера и возврат исходных параметров.

Для публичного фильтрующего AdGuard DNS Default на Android укажите имя dns.adguard-dns.com в поле частного DNS. Для обычной DNS-настройки Windows используются IPv4 94.140.14.14 и 94.140.15.15. Если нужен личный журнал и правила кабинета, используйте собственный endpoint, а не эти общие адреса.

Адреса ниже сверены с официальной GitHub-базой знаний 1 ноября 2026 года. DNS-запрос содержит имя ресурса; после получения адреса браузер создаёт отдельное соединение для загрузки. Настройка резолвера не создаёт VPN и не удаляет любой рекламный блок внутри страницы.

Адреса публичного Default

Официальный список провайдеров DNS приводит:

Способ Значение
Обычный DNS, IPv4 94.140.14.14 и 94.140.15.15
Обычный DNS, IPv6 2a10:50c0::ad1:ff и 2a10:50c0::ad2:ff
DNS-over-HTTPS https://dns.adguard-dns.com/dns-query
DNS-over-TLS Имя dns.adguard-dns.com; в поддерживающем такую запись клиенте — tls://dns.adguard-dns.com

Не смешивайте форматы. В Android-поле имени поставщика не вставляют DoH-URL, а в обычное IP-поле — веб-адрес с https://.

Android: настроить частный DNS

Эта ветка для устройства, в настройках которого есть режим Private DNS / Частный DNS с вводом имени поставщика. Названия разделов производителя могут различаться, поэтому удобно найти «DNS» поиском настроек.

  1. Откройте настройки сети и раздел частного DNS.
  2. Запишите текущий режим, чтобы можно было вернуть его.
  3. Выберите вариант ввода имени поставщика, а не автоматический режим.
  4. Введите dns.adguard-dns.com без схемы и пути.
  5. Сохраните настройку и откройте обычный сайт.

Ожидаемый результат: настройка принимается и разрешение имён продолжает работать. Если система сообщает, что соединение с частным DNS невозможно, верните прежний режим и разберите доступность выбранного способа в этой сети. Отключать проверку TLS не нужно.

Для личного AdGuard DNS в KB приведено имя вида {Your_Device_ID}.d.adguard-dns.com. Это обозначение формата, не готовый адрес: возьмите имя именно своего устройства из кабинета.

Windows 10/11: обычные DNS-адреса адаптера

Эта ветка задаёт обычный системный DNS, не включает DoH автоматически. Шаги соответствуют настройке адаптера, которую официальная база знаний описывает для DNS-клиентов.

  1. Откройте Панель управления → Сеть и Интернет → Центр управления сетями.
  2. Выберите Изменение параметров адаптера.
  3. Откройте свойства активного подключения — Wi-Fi либо Ethernet.
  4. Выберите IP версии 4 (TCP/IPv4) → Свойства.
  5. Запишите прежний режим и адреса. Выберите ввод DNS-серверов и укажите 94.140.14.14 и 94.140.15.15.
  6. Сохраните изменения. Не меняйте ради DNS IP устройства и основной шлюз.

Если используется IPv6, учитывайте и его DNS-настройку: официальные адреса приведены в таблице. Не считайте изменение одного семейства доказательством, что другой DNS-путь отсутствует.

Проверить запрос

В Windows откройте командную строку и выполните документированный DNS-тест:

nslookup example.org

Посмотрите строки Server/Сервер и Address/Адрес используемого резолвера, затем ответ для example.org. При прямой настройке публичного DNS ожидается соответствующий адрес AdGuard. Если утилита обращается к другому серверу, проверьте активный адаптер, IPv6 и настройки сети.

Этот тест относится к утилите и системному пути. Браузер с собственным защищённым DNS может использовать другую настройку. Для личного endpoint дополнительно сопоставьте запрос с журналом выбранного устройства, если ведение журнала включено.

Для чего нужен DoH-адрес

В клиенте или браузере с поддержкой ручного DNS-over-HTTPS укажите полный https://dns.adguard-dns.com/dns-query в предназначенное для DoH поле. Не копируйте его в обычное поле DNS-IP. Возможность и порядок ввода зависят от конкретного клиента.

Шифрование обмена с резолвером и фильтрация — разные свойства. DNS не исправляет ошибки аккаунта и не гарантирует доступ к любому ресурсу. Если реклама и полезные данные приходят с одного домена, его блокировка может затронуть оба.

Личный кабинет и возврат настроек

Для управляемого личного сервера откройте сайт AdGuard DNS по партнёрской ссылке, создайте своё устройство предусмотренным способом и используйте его параметры. Публичный Default не появляется автоматически в личном журнале.

Если после настройки сеть работает неправильно, верните записанные значения или прежний автоматический режим. Проверьте исходный интернет и продолжайте по диагностике DNS. Не переводите весь домашний роутер на новую схему, пока один клиент не прошёл такую приёмку.

FAQ

Какое имя ввести в поле частного DNS на Android?

Для публичного фильтрующего AdGuard DNS используйте dns.adguard-dns.com, без префикса https:// и пути. Для личной конфигурации возьмите собственное имя из кабинета. Поле имени поставщика и поле полного DoH-адреса требуют разных форматов.

Какие IPv4 указаны у публичного AdGuard DNS Default?

В официальной базе знаний указаны 94.140.14.14 и 94.140.15.15. Это обычные DNS-адреса, не VPN-серверы. Перед изменением запишите прежние значения; настройка IP сама по себе не включает шифрованный DoH или DoT.

Какой DoH-адрес использовать в совместимом клиенте?

Для публичного Default в базе знаний приведён https://dns.adguard-dns.com/dns-query. Вставляйте весь адрес в поле, которое поддерживает DNS-over-HTTPS. В системном поле имени частного DNS Android нужен другой формат, без схемы и пути.

Что покажет команда nslookup example.org?

Она выполняет DNS-проверку и обычно показывает используемый утилитой сервер и ответ для example.org. Это полезно после настройки обычного системного DNS. Результат не доказывает, что браузер с собственным защищённым DNS использует тот же путь.

Почему публичный Default не появился как устройство в личном кабинете?

Публичный резолвер и персональный endpoint — разные способы подключения. Чтобы видеть запросы выбранного личного устройства, используйте выданные ему параметры и включённый журнал. Не подставляйте чужой идентификатор и не ожидайте личной привязки от общего адреса.
