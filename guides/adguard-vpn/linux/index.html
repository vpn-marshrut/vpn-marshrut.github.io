AdGuard VPN для Linux: реальный CLI, TUN и локальный SOCKS5

Как начать с официального AdGuard VPN CLI на Linux: проверка выпуска, вход, команды, различия TUN/SOCKS5 и взаимодействие с AdGuard CLI.

Для Linux используйте официальный AdGuard VPN CLI: получите подходящий стабильный выпуск, проверьте подпись, выполните login, connect и status. Для отключения есть disconnect. Не заменяйте этот клиент Windows EXE или произвольным OpenVPN-профилем.

Ниже — команды из текущих официальных KB и README, прочитанных 1 ноября 2026 года. Редакция не запускала VPN-туннель и не проверяла его доступность в вашей сети. CLI является отдельным продуктом: публичный GitHub-репозиторий не означает открытый исходный код самого клиента.

1. Получить и проверить выпуск

Откройте официальные выпуски AdGuard VPN CLI, выберите стабильный пакет для своей ОС и архитектуры и распакуйте его. Beta и nightly не нужны только потому, что вы впервые устанавливаете клиент.

В официальном README описана проверка файла подписи рядом с бинарником. Для неё нужен GPG. После получения файлов перейдите в их каталог и используйте опубликованный производителем ключ:

gpg --keyserver 'keys.openpgp.org' --recv-key '28645AC9776EC4C00BCE2AFC0FE641E7235E2EC6'
gpg --verify ./adguardvpn-cli.sig ./adguardvpn-cli

Пути относятся к распакованным файлам; при другой структуре укажите фактические расположения. Сверьте fingerprint с официальным README. Ожидается успешная криптографическая проверка соответствующего бинарника. Сообщение о неподтверждённом доверии к User ID отличается от ошибки подписи; не меняйте ожидаемый ключ ради «успеха».

При несовпадении файла, подписи или ключа остановитесь до запуска. В документации есть и установочный сценарий, но скачанный код с административными правами не следует выполнять вслепую.

2. Прочитать справку и войти

Из каталога проверенного бинарника:

./adguardvpn-cli --help-all
./adguardvpn-cli login

В описанном меню авторизации b открывает страницу входа в браузере. Завершите её своим аккаунтом. По документации успешный вход отмечается Successfully logged in в терминале.

Затем проверьте:

./adguardvpn-cli license
./adguardvpn-cli config show

Результат: видны ожидаемый аккаунт/доступ и текущая конфигурация. Не публикуйте вывод с email и личными параметрами. Для удалённой машины заранее сохраните независимый доступ: изменение маршрута может прервать ваш единственный SSH-сеанс.

3. Выбрать TUN и подключиться

Если нужен системный туннель по его правилам, официальный клиент предусматривает:

./adguardvpn-cli config set-mode TUN
./adguardvpn-cli list-locations
./adguardvpn-cli connect
./adguardvpn-cli status

TUN требует административных прав для сетевых действий. Выполняйте предусмотренный клиентом запрос прав, не переносите пароль в командную строку или чужой сценарий. Если нужна конкретная локация, используйте поддерживаемый параметр из справки, а не произвольное имя сервера.

Результат: status сообщает об установленном соединении. Затем отдельно выполните нужное действие приложения; статус клиента не является тестом всех программ и сайтов.

Альтернатива: только приложения с SOCKS5

Для локального прокси режим задаётся иначе:

./adguardvpn-cli config set-mode SOCKS
./adguardvpn-cli connect

В документации SOCKS5 по умолчанию слушает 127.0.0.1:1080. Настройте нужное приложение на этот прокси. Без такой настройки оно не начинает использовать VPN автоматически. Не меняйте прослушивание на все интерфейсы ради одного локального клиента.

Проверьте способ разрешения имён приложения. В инструментах, которые это поддерживают, socks5h обозначает передачу имени прокси, а обычная локальная DNS-настройка может работать другим путём. Выбор SOCKS5 сам по себе не подтверждает отсутствие утечек.

4. Отключить и вернуть исходный режим

./adguardvpn-cli disconnect
./adguardvpn-cli status

Повторите обычное сетевое действие. Результат: VPN остановлен и исходная сеть работает. Сохраните выбранный режим и параметры, которые действительно проверены на вашем устройстве.

Если одновременно нужен AdGuard CLI-блокировщик, учтите документированный routing loop у сочетания автоматического proxy блокировщика и TUN VPN. Используйте одну из официальных альтернатив с понятной маршрутизацией, а не включайте оба режима наугад. Для адресных правил есть инструкция исключений.

FAQ

Как войти в AdGuard VPN CLI после установки?

В официальной инструкции используется команда adguardvpn-cli login с продолжением авторизации в браузере. Затем adguardvpn-cli license показывает связанный доступ, а config show — конфигурацию. Сверяйте справку установленной версии и не публикуйте вывод с личными сведениями.

TUN и SOCKS5 направляют одинаковый трафик?

Нет. TUN работает через системный виртуальный интерфейс и маршруты. В SOCKS5 приложения явно настраиваются на локальный прокси; без этого их трафик не перенаправляется автоматически. Отдельно проверяйте, где приложение разрешает доменные имена.

Почему совместная работа с блокировщиком CLI может зациклиться?

Официальная документация описывает routing loop при TUN у VPN CLI и автоматическом proxy-режиме AdGuard CLI. Нужна одна из документированных альтернатив с явной схемой прокси и исключений, а не включение всех режимов одновременно.

Нужно ли брать beta, если стабильный выпуск не подключается?

Не автоматически. Сначала сохраните ошибку, исходную сеть, режим и параметры доступа. Beta и nightly — отдельные каналы с собственными рисками. Смена канала без диагноза не подтверждает совместимость и не заменяет проверку подписи установочного файла.
