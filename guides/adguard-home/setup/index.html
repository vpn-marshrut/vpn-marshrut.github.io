Как развернуть AdGuard Home дома: узел, DNS-клиенты и возврат настроек

План установки собственного AdGuard Home: официальный выпуск, интерфейсы доступа, вышестоящий DNS, один тестовый клиент и безопасное расширение на сеть.

Чтобы запустить AdGuard Home в домашней сети, установите собственный DNS-узел, пройдите его начальный мастер и подключите один тестовый клиент. После проверки можно изменить выдачу DNS на роутере. Home не требует покупки VPN и не создаёт туннель для телевизора или телефона.

Ниже — пример первого запуска нативного пакета на Linux и приёмка клиента Windows. Команды сверены с официальной KB 1 ноября 2026 года; редакция не выполняла установку на вашем оборудовании. Для контейнера или другой ОС используйте предназначенную им ветку, не копируя управление службой Linux.

1. Подготовить доступный узел

Выберите машину, которая будет включена, когда домашним устройствам нужен DNS. Запишите её адрес в своей сети и предусмотрите постоянство этого адреса. Остановка единственного резолвера может лишить клиентов разрешения имён.

Установка и панель управления должны оставаться в доверенной локальной среде. Не открывайте DNS и начальный мастер всему интернету ради домашнего сценария. Сохраните прежние DNS-параметры тестового клиента и доступ к управлению роутером.

2. Получить пакет и проверить происхождение

Откройте официальные выпуски Home, выберите стабильный пакет для Linux и своей архитектуры. Для её определения в KB используется:

uname -m

В руководстве сопоставлены x86_64 с amd64, а aarch64/arm64 — с arm64. Для другого результата используйте соответствующий поддерживаемый пакет, не угадывая по названию компьютера.

Распакуйте архив и проверьте подпись по инструкции безопасного размещения. До запуска сверьте официальный ключ и результат проверки. Каталог и бинарник не должны быть доступны посторонним для изменения.

3. Пройти начальный мастер

Из каталога распакованного бинарника выполните предусмотренный первый запуск:

sudo ./AdGuardHome

Программа выводит адреса начального веб-интерфейса. Откройте подходящий адрес локально и пройдите мастер: выберите интерфейсы DNS/управления, настройте вход и завершите конфигурацию. Первый мастер по документации использует порт 3000; проверьте доступ только для своей доверенной среды.

Результат: конфигурация сохранена, доступ к управлению понятен. Если нужный порт занят, сначала выясните роль существующей службы — не удаляйте случайный DNS-процесс ради продолжения.

4. Зарегистрировать службу

После завершения мастера остановите первоначальный процесс штатно, затем из того же каталога используйте документированное управление:

sudo ./AdGuardHome -s install
sudo ./AdGuardHome -s status

Если служба установлена, но не запущена:

sudo ./AdGuardHome -s start

Результат: команда состояния показывает работающую службу. Для контролируемой остановки предусмотрено -s stop, для перезапуска — -s restart. Сначала работайте с одним узлом и клиентом, а не переводите сеть целиком.

5. Выбрать upstream и фильтрацию

В DNS-настройках укажите выбранный вышестоящий резолвер и базовый набор правил. Например, официальный список AdGuard приводит нефильтрующий DoH https://unfiltered.adguard-dns.com/dns-query. Он позволяет отдельно оценивать локальные правила Home, не смешивая их с дополнительной внешней фильтрацией.

Если upstream сам блокирует домен, локальное разрешение в Home не обязано отменять решение внешнего резолвера. Это важно при разборе исключений. Настройка DNS не меняет автоматически маршрут загрузки веб-страницы.

6. Принять один тестовый клиент

На Windows-клиенте задайте DNS-адрес вашего Home через свойства активного сетевого адаптера, сохранив прежний режим. Затем откройте командную строку:

nslookup example.org

В выводе проверьте сервер и сравните с адресом Home, затем найдите соответствующий запрос в Query log. Это последовательность из официального Home FAQ.

Результат: утилита использует ожидаемый DNS и запрос наблюдается у правильного клиента. Браузер с отдельным защищённым DNS может обходить системную настройку, поэтому его проверяют отдельно. Не считайте один запрос доказательством охвата всей сети.

Расширение и возврат

Только после успешного теста меняйте выдачу DNS на роутере по его инструкции. Учитывайте IPv6 и то, видит ли Home отдельные устройства или только пересылающий роутер. Не включайте второй DHCP-сервер без понимания действующей схемы.

При ошибке верните прежний DNS клиента. Для выборочной блокировки используйте исключения Home, а для DNS-пути — диагностику. Резервные копии, обновления и доступность собственного узла остаются частью эксплуатации Home.

FAQ

Можно ли поставить Home на компьютер, который выключается ночью?

Технический выбор узла должен учитывать доступность: когда единственный DNS-сервер выключен, зависящие от него клиенты могут потерять разрешение имён. Для постоянной домашней схемы нужен доступный узел и понятный план возврата DNS.

Нужно ли открывать панель Home в интернет для домашней сети?

Для обычного локального сценария это не требуется. Выберите интерфейсы прослушивания и доступ клиентов под свою схему. Публичная доступность требует отдельной настройки безопасности и не является способом исправить один домашний запрос.

Когда переводить DNS всей сети на Home?

После установки проверьте один тестовый клиент: обычные сайты, нужную фильтрацию и наблюдаемые запросы. Сохраните прежние DNS-параметры. Затем меняйте выдачу на роутере и проверяйте остальные устройства, учитывая собственный DNS браузеров и IPv6.

Даст ли установка Home VPN для телевизора?

Нет. Home обрабатывает DNS-запросы на вашем оборудовании, а не создаёт автоматически VPN-туннель для телевизора. Загрузка видео идёт отдельным соединением. Если нужен другой сетевой маршрут, это отдельная задача совместимости клиента или роутера.
